# Notes for Claude

Bounty TCG is a One Piece Card Game tabletop. The same game page runs in two places: as a claude.ai artifact (Ryan's online page) and inside the Electron desktop app built from this repository.

## Where things live

- `page/bounty-tcg.html` is the source of truth for the game. It is written for claude.ai's `window.claude.use(...)` capabilities (room, db, assets, user, sample).
- `desktop/net.js` provides those capabilities in the desktop app: PeerJS rooms (the room namespace itself is the shared lobby), localStorage db with `seed.json`, card art on disk, and card reading with the player's own Claude API key. It also shows update banners, and provides optional email accounts (Firebase Auth + Firestore over REST; `FB_CONFIG` near the top of the db section holds Ryan's web config, `tools/firestore.rules` the security rules). Signed in, a player's `data/users/<uid>/...` and the shared `ranks` leaderboard live in Firestore; with no config the app works as before.
- `page/effects.json` holds every card's abilities, built from the official card text by `tools/build_effects.py` (run it on the English card files from github.com/buhbbl/punk-records). The game uses these first and only asks Claude to read cards that aren't in it. Rebuild it when a new set comes out, and publish it with the artifact as a supporting file. `--report` prints how many abilities the game carries out by itself and the wording it still leaves to the player.
- `tools/build.py` patches the page for the desktop (bundled fonts, wording that assumed claude.ai accounts) and builds `dist/kit`. Every patch must match exactly once, or the build stops.
- `desktop/main.src.js` is the Electron main process. It serves `app://bounty/` and runs the updater.
- The full app (with card art) is a zip on Ryan's Google Drive, linked at the top of `README.md`. The app's "Open download page" button opens this repository's page, so a new Drive link only needs changing in the README.

## Updates

Installed copies read `https://raw.githubusercontent.com/ryanmTCG/Bounty-TCG/main/updates/latest.json` at launch.

Ryan wants the desktop app updated only once 10 changes have piled up, unless he asks for an update sooner. The claude.ai artifact still gets each change right away. For each change to the game:

1. Make it in the source (usually `page/bounty-tcg.html`), republish the artifact, and commit and push. Source commits don't reach players.
2. Add one line about it to `updates/pending.md`.
3. Don't copy it onto Ryan's PC: his copy gets it from GitHub with everyone else's.

To publish, once `updates/pending.md` lists 10 changes or Ryan asks for an update:

1. Bump `version` in `version.json`.
2. Run `python3 tools/build.py` and the tests, then `python3 tools/publish_update.py`. It refuses with fewer than 10 changes unless you pass `--now` (only when Ryan asked). The notes default to the pending list, which it empties.
3. Commit `updates/` and push to `main`.

Whatever is on `main` in `updates/latest.json` reaches every player, so only publish tested builds. Changes to `main.src.js` or `preload.js` need `SHELL_VERSION` raised, and only reach players through a full app download. Raise `version.json`'s `shell` to match only when the page depends on the new shell: players on an older shell are then sent to download the full app.

## Rules

- Never commit card art, `*.webp`, or Bandai's DON!!/sleeve images. `private/static/` holds the latter locally and is gitignored. Update bundles skip them too.
- Run the tests in `tests/` against `dist/kit/app` after building: `xvfb-run -a node tests/testupdate.mjs`, `testlobby.mjs`, `testlegal.mjs`, `test2p.mjs`, `testranked.mjs`, `testaccount.mjs` (accounts against a local stand-in for Firebase), `testrejoin.mjs`, `testbattle.mjs`, `testtimer.mjs`, `testfriends.mjs`, `testbot.mjs` (the computer opponent), `testdeck.mjs` (deck import/export and checks), `testtutorial.mjs`, `testeffects.mjs` (card abilities the game carries out), `testfair.mjs` (public and ranked tables lock the free board tools), `testrules.mjs` (game rules from the official Comprehensive Rules, and the computer using its own card abilities), `testreplay.mjs` (match replays, and the computer's Easy / Normal / Hard), `testtour.mjs` (tournaments with three players), `testmeta.mjs` (shared match records and the Meta page, against `tests/fakefire.mjs`, a stand-in for Firebase), `testseason.mjs` (ranked steps and seasons), `testexpert.mjs` (the computer's Expert and Master levels and the decks it can play), `testfeed.mjs` (replay codes and the Recent games feed), `testreport.mjs` (Report a problem and Bug reports), `testshare.mjs` (deck codes, the deck picture and the opponent's list after a match), `testquick.mjs` (the Find a match queues and their counts, watching a live match, and muting quick chat). The multiplayer tests start a local PeerJS server from the `peer` package.
- Every open copy of the game sits in the shared lobby with its friend code, name and status (`lobbyUpdate`), so friends can see each other online. A challenge is a `ch` note in that presence naming a friend code and a `friend-...` table, and a decline is a `dc` note. Tests run offline, so a launch without the local PeerJS server logs failed connections to the public one.
- The game follows the official Comprehensive Rules (en.onepiece-cardgame.com/pdf/rule_comprehensive.pdf): attacks only on your own turn with an active card and one at a time, a Blocker can't block an attack on itself, an empty deck loses, a 6th Character makes you trash one of the other 5 (not a K.O.), and a used Event goes to the trash. `playTiming()` holds paid plays from hand to their timing: Characters, Stages and [Main] Events on your own turn outside a battle, [Counter] Events while you're attacked. `blockerNow()` and `cantAttack()` read a card's own conditions ("[DON!! x1] This Character gains [Blocker]", "This Leader cannot attack."). The computer opponent (`botMain`, `botAbility`, `botFxStep`) carries out its own cards' abilities through the same effects engine (On Play, Activate: Main, Events, Triggers, Counter Events, On Your Opponent's Attack, End of Your Turn), plays Stages, keeps DON!! back for a [Counter] Event in hand, and plays like the strategy guides: weaker attackers first, rested Characters before a healthy Leader, the Leader once you're at 2 Life, and everything at the Leader when it can win that turn (`botLethal`).
- Preview sets: `RELEASES` holds each set's English release date. Before it, `legalOf()` returns `"pre"` for its cards: they're only legal in the `pre` lobby format (Standard + previews), Casual and practice. Add the next set there when its preview cards go into `data/names` and `data/card-text-extra.json`. Japan gets sets a day after English now, so there's no separate Japanese pool.
- Public lobby tables (`S.pubt`) and ranked matches have no free board tools (`boardTools()`): drawing, looking at the deck or Life, healing, DON!!, resting and moving cards by hand only work through `fair()`/`fairMove()`, which allow them while a card's ability is left to the player and its wording names that thing. Any new manual tool needs the same check.
- After changing the page, the claude.ai artifact needs republishing separately; the desktop app gets it through an update.
- Tournaments live in the host's lobby presence (`tn`, from `tourPub()`), kept on the host's computer in `bounty:tour` (`TOUR`). A sign-up is the player's own presence `tj` with their deck packed by `deckPack()`, kept in `bounty:tourme` (`TME`); the host's `tourHost()` (run from `tourTick()` on every lobby change) seats sign-ups, drops online players who withdrew, and moves the single-elimination bracket on (`T.rd`, rounds of `[a, b, winner]`, -1 for a bye or no winner yet). A result is the loser's own report `tl`, sent by `tourCheck()` when they concede or lose at a `tour-<id>-<round>-<match>` table (`S.tour`, which is a public table: `S.pubt`); the host can also give a match to a player. Decklists are only shown to the host until it's done, then published in `tn.dl`. Anything read from presence goes through `cleanTour()`/`deckUnpack()`.
- Ranked bounty is Elo on the bounty scale: `rankStep(me, opp, won)` (K = ฿55,000, ฿400,000 apart is 10 to 1, a win ฿5,000 to ฿50,000) and `rankLossStep()` scales a loss by `LOSS` for the loser's rank. The opponent's bounty comes from their presence `rb` (`S.oppB`, falling back to your own for older copies). Seasons are UTC calendar quarters (`seasonKey()`, `"2026q4"` is Season 1): `rankSeason()` tags a record with `s`, and in a new season keeps the old bounty in `ps` (last 12), halves it to ฿300,000 at most and zeroes the record, for `RANK` on load and the cloud doc in `rankClaim`/`rankLossCloud`. `results` carry `s` and a win only counts with a result from the same season. The leaderboard shows the current season. The Firestore rules check all of this (`newSeason()`, `sameSeason()`).
- Shared replays: `replays/<id>` holds `{v, t, by, e}` with `e` the same text as a replay file. A signed-in player's "Share code" (`rpShare`) puts one up under an 8-letter code (shown as ABCD-EFGH, kept on the local entry as `code`); "Open a code" (`rpCode` → `rpFetch` → `rpImport`) adds it to the list. `gameCheck()` also puts up each shared match's replay without hands (`rpFeedText`) under its games id and sets `rp` on the record, and the Meta page's Recent games (`modal.view`, one row per match) plays it through `rpFeed` → `rpCheck` → `rpOpenFrames` without keeping it. Everything read back is untrusted and goes through `rpCheck()`.
- Report a problem (`openReport`, from Home and Profile) builds a report with `reportBuild()`: the message, `APPV` (from `version.json`), the game so far as a replay entry (`e`, from `REC`), and `reportState()` (both sides at practice tables, `oppM` online, the log, `fxCur`, and `ERRS`: window errors, rejections and console warnings/errors, last 30). Signed in, `reportSend()` writes `reports/<id>` `{v, t, by, ver, msg, where, z}` (z: the packed `{st, e}`); anyone can save it as a file, which `rpCheck()` also opens as a replay. Only admins read reports: an `admins/<uid>` document Ryan adds in the Firebase console, checked by `reportsAdmin()`, which shows Profile > Bug reports (`openReports`, `reportUnpack` with `rpInflate`'s cap, `reportWatch`, `reportDetails`).
- Shared match records: `gameCheck()` writes `games/<match>-<player>` when a signed-in player who shares (`shareOn()`, `STATS.ns` off) finishes an online match: their own Leader, the opponent's, the result, how it ended and only their own decklist (`deckPack`); an opponent who doesn't share (`ns` in their presence) isn't named. `gamesLoad()` reads the newest 1000 (`orderBy("t", "desc").limit(1000)`, which `desktop/net.js` supports for local and Firestore collections) and the Meta page (`openMeta`, `metaAgg`, `metaLeader`) adds them up. Firestore rules for the shared collections are in `tools/firestore.rules`; Ryan pastes them into the Firebase console.
- Replays: `recTick()` records every change to both players' public boards (the presence, through `RP_KEEP`) as diff frames, from `doPublish`, `onPeers` and `botSide`, keyed by the match id `S.rid`. Your own hand rides along as `hd`, and both hands at practice tables; never record an online opponent's hand. `rpSave` packs the last `RP_MAX` into localStorage `bounty:replays` with gzip. Playback reuses watch mode (`WATCH.replay`, `renderWatch`, `rpBar`), and table actions are blocked while `RPV` is open. "Save file" writes one as `{bounty: "replay", v: 1, e}` (`rpDownload`); opening a file goes through `rpImport`, which treats it as untrusted: size caps packed and unpacked (`rpInflate` stops a gzip bomb), every frame's shape checked, only `RP_KEEP` keys kept, and names cleaned.
- The computer's difficulty is `PR.diff` (0 Easy, 1 Normal, 2 Hard, 3 Expert), read through `botLv()` (`diffOf()` checks a stored value). Normal is the strategy-guide play described above; the tutorial and tests that don't pick one get Normal. Easy, Hard and Expert only change choices, never what the rules allow. Expert is Hard plus: `botPlan()` picks the plays that spend the most DON!! (keeping back what `botCtrKeep()` wants), `PR.bwin` skips plays on a turn `botLethal()` says it can win, `botCtrSet()` counters with the least Counter, and it takes Leader hits at 4+ Life. Master (4) is Expert plus a look at your next turn: `botThreat()` counts the hits your Leader and Characters could land with your DON!! plus 2 against its Life and home Blockers (`PR.bdg` at the start of its turn), `botPlan(don, danger)` then favors Blockers, its Blockers stay home, and `botTargetAhead()` scores each target (Leader hits by your Life, K.O.s by cost, Blocker and how much that Character threatens it) weighed by the odds your counters don't stop it.
- The computer's deck in practice setup is `#f-odeck` (`odeckOpts`, `odeckFill`, saved as `odeck`): the same as yours, the list typed in, a tournament deck from `BOT_DECKS` (packed with `deckPack()`, from onepiecetopdecks.com; refresh them when the meta moves and check each is legal in Standard), or the Meta page's most played list per Leader (`BOT_META`, `odeckMeta()`). The Meta page's lists also have "Play the computer with it" (`metaBot`).
- Card data in `data/names` was checked against the official English card list (punk-records): compare colors, types, costs, power and Counters again when adding a set.
- Card abilities also cover face-up Life (`up` on a Life card, `lu` in the presence), resting your own cards or a DON!! to pay a cost (the `dn` flag and the "Rest a DON!!" button), and "cannot be K.O.'d / removed by effects" (`shielded()`, checked in `applyMarkReqs`; a battle K.O. is sent with `v: -1` so it isn't stopped). Revealing the top card of your deck or Life (`reveal`, then `playRv`, `addRv`, `rvPlace`, `rvKw` on `m.rv`; conditions about "that card" go through `rvCheck`), revealing cards from your hand as a cost (`revealHand`) and power that lasts through the opponent's next turn are carried out too. That power is `nx` on a step: your own card keeps it in `f.nx` past your end of turn, and a mark request with `nx: 1` puts it in the opponent's `f.nt`, which their start of turn keeps and their end of turn clears.
- "Negate the effect of" is the `ng` mark (`negated()`): it turns off that card's own abilities, keywords, statics, Blocker, `shielded()`, On K.O. and On Your Opponent's Attack until its owner's next start or end of turn. A step with `ng: true` (OP17-063's "negate ... and K.O. it") sends the mark before the K.O., so "cannot be K.O.'d by effects" and On K.O. don't apply. "All of your Character cards without a Counter have a +1000 Counter" is `hc` on an ability, read through `ctrOf()` wherever a hand card's Counter is used.
- `fxLimits()` reads what a step may target from its clause after any leading "If ...," (a condition's "{X} type Characters with a cost of 5 or more" isn't a limit), and "base power" compares printed power (`bp`). In `tools/build_effects.py`, `clauses()` keeps costs, "and"/"then" second actions and a "Draw N, look at" as separate steps; check `--report` and a diff of `page/effects.json` after changing it.
- `fxLimits()` also reads colors, attributes (`attr`, a list: "<Special> or <Wisdom>"), several `{types}` (any one of them; `orTrig` for "{X} type Characters or Characters with a [Trigger]"), [Trigger] and [Blocker], DON!! given (`don`), a named Leader (`ldName`), a named card that can be a Stage, "no base effect" and "a cost equal to or less than ... Life cards". `cardFilter()` (searches, plays, hand and trash picks) splits "X or Y" into parts (`cardFilter1`) and takes either one; "play ... from your hand or trash" is `playSpec().from === "both"`. Cost changes that outlast the turn use `f.cx`/`f.ct`, the same way power uses `nx`/`nt`.
- `step()` in `tools/build_effects.py` leaves to the player (an "other" step) what the engine can't carry out exactly: a choice between two actions, "instead" replacements (the whole ability, apart from the `rp` ones), "at the end of this turn", "any number of", "different card names", a cost that counts DON!!, two plays at once, and targets that can be an opponent's Stage or DON!!. Always-on text with two sentences is one ability per sentence. `abilityNow()` offers [Opponent's Turn] abilities on the opponent's turn and "would be K.O.'d ... instead" on either turn.
- Abilities that fire by themselves go through `abFits(a, cause)`: [Your Turn] / [Opponent's Turn] text, and `koBy` ("When this Character is K.O.'d by your opponent's effect" is an [On K.O.] with `koBy: "opp"`, "by an effect" `"fx"`) against how the card was K.O.'d (`runAbility`'s `cause`: "opp" from `applyMarkReqs`, "battle", "own" through `koCause` in `fxRemoveOwn`, null when moved by hand, which lets it run).
- "If this Character would be K.O.'d / removed from the field, you may X instead" is `rp` on the ability (`replacement()` in `tools/build_effects.py`: what it stops in `on`, which Characters in `w`/`f`/`n`/`x`, the cost X as `steps`). `rpOffer()` holds the removal in `applyMarkReqs` (cause "opp", or "battle" for `v: -1`) and `defResolve` and offers the cost as a job with `m.rpl`; "Don't use it" (`fxFinish(false)`) offers the next card that could, then removes it. `rt` steps ("add it to the top of your Life cards") act on the card being kept. The computer pays when it can, except on Easy (`botRunJob` keeps its job apart from yours).
- "When a DON!! card on your field is returned to your DON!! deck, ..." and the like are `wh` on the ability (`when_spec()`), and `whenFire(e, x)` offers them when it happens: `don` (fxrdok, returning DON!! by hand), `rest` (attacking, blocking, effects, the Rest menu), `event` and `play` (moveCard), `dmg` (your attack resolved with less opponent Life, or cmbapply), `hit`, `ko` (`koDone`; your opponent learns from `kc` in the presence), `rm` and `discard`. `whenWho()` reads which wording a Character fits before it leaves the field. `rushNow()` doesn't take the card list's Rush keyword for a card whose ability only gains [Rush].
- The deck editor's stats show opening hand odds (`hyp1`, `bdOddsHTML`) and a practice hand (`BDH`, `bdHand`): deal 5, mulligan once, draw ahead. It goes away when the deck changes.
- Sharing decks: a deck code is `BTCG1-` and `deckPack` in URL-safe base64 (`deckCode`, `deckFromCode`, read wherever a list is pasted through `codeOrList` and in `readDeckFields`). The Deck editor's Share (`openDeckShare`) draws the deck on a canvas (`deckCanvas`) to save or copy. When a match ends, a player who shares (`shareOn()`) adds their packed list as `dl` to their presence (`pubFull`, and a publish when the opponent's concession arrives); `oppModel` checks it and the end banner's "See their deck" opens `openOppDeck`.
- Find a match (`openQuick`, `findMatch(k)`): k 1 is ranked, 2 a quick match (a public Standard table, `S.quick` and `S.pubt`). Both are lobby entries with `r: k` that Lobbies hides; `findMatch` joins the oldest waiting one or opens its own. The lobby presence's `mk` ("r"/"q") says which kind of match a player is in, and `queueCounts(k)` counts the waiting entries and the players in a match for the `.lbcount[data-q]` lines.
- Watching: friends-only casual matches put their room in the lobby presence's `w` (friends only, through `onlineMap`), public, quick, ranked and tournament matches in `pw` with the player's Leader `ld`. `liveMatches()` lists the `pw` tables on the Find a match page (`#live-list`, `livewatch:`), and `watchTable()` joins without a seat. Quick chat (`QC`) is a fixed list, so new phrases only go at the end (older copies ignore an index they don't have); `qcMute` hides the opponent's for the match.
